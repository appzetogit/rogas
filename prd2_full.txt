1. App Overview 
 
The Vendor App is used by all meal providers: home cooks, cloud kitchens, restaurants, and catering companies. Key principle: all deliveries are handled by 
fleet partners — vendors NEVER self-deliver. Vendor role is: prepare food, mark ready, hand to driver. Everything else is handled by the platform.

Vendor Settlement Statement — VAT Breakdown (v3.0) 
// Weekly settlement calculation for vendor:​
async function calculateVendorSettlement(vendorId, weekStart, weekEnd) {​
  const orders = await Order.find({​
    vendor_id: vendorId,​
    delivery_date: { $gte: weekStart, $lte: weekEnd },​
    status: "delivered"​
  })​
​
  const vendor = await Vendor.findById(vendorId)​
  const vatRate = await remoteConfig.get("food_vat_rate_" + vendor.city)​
  // e.g. 0.08 for Warsaw (8% — corrected from 5%)​
​
  let grossFoodRevenue = 0, commissionAmount = 0​
  orders.forEach(order => {​
    grossFoodRevenue += order.meal_price​
    commissionAmount += order.meal_price * vendor.commission_rate​
  })​
​
  // VAT calculations:​
  const foodNetRevenue = grossFoodRevenue / (1 + vatRate)​
  const foodVatAmount = grossFoodRevenue - foodNetRevenue​
  // Note: food VAT "belongs" to vendor — they declare it to tax authority​
  // DailyMealBox passes the gross food amount to vendor​
​
  const commissionNet = commissionAmount / 1.23  // 23% VAT on commission​
  const commissionVat = commissionAmount - commissionNet​
  // Commission VAT belongs to DailyMealBox​
​
  const vendorNetPayout = grossFoodRevenue - commissionAmount​
  // Vendor receives: gross food - commission (both inclusive of VAT)​
​
  // Settlement statement stored:​
  return {​
    period: { start: weekStart, end: weekEnd },​
    orders_count: orders.length,​
    gross_food_revenue_pln: grossFoodRevenue,​
    food_vat_rate: vatRate * 100 + "%",   // 8%​
    food_vat_amount: foodVatAmount,        // vendor declares this​
    food_vat_owner: "vendor",​
    platform_commission_gross: commissionAmount,​
    platform_commission_vat: commissionVat, // DailyMealBox declares this​
    platform_commission_net: commissionNet,​
    vendor_net_payout: vendorNetPayout,​
    kitchen_partner_id: vendor.kitchen_partner_id || null,​
    // If home cook: DailyMealBox pays Kitchen Partner, KP pays cook​
  }​
}​
​
// Home cook settlement (via Kitchen Partner):​
if (vendor.kitchen_partner_id) {​
  // DailyMealBox pays Kitchen Partner:​
  const kpPayout = vendorNetPayout  // full net goes to KP​
  // Kitchen Partner pays home cook:​
  const cookPayout = vendorNetPayout * kitchenPartner.settlement_split  // e.g. 85%​
  const kpFee = vendorNetPayout * kitchenPartner.management_fee_pct     // e.g. 15%​
}

10.1 Kitchen Partner Model for Home Cooks  
Home cooks without a registered company must link to a Kitchen Partner before going live. The Kitchen Partner is a registered Sp. z o.o. that holds the EU 
food safety certification, issues food invoices on behalf of the home cook, receives payment from DailyMealBox, and pays the home cook their share 
(typically 85%). 
Aspect 
Restaurant (own company) 
Home Cook (via Kitchen Partner) 
Invoice issuer 
Vendor issues own food invoice (or DMB self-invoices) 
Kitchen Partner issues food invoice to DailyMealBox 
VAT registration 
Vendor has own NIP. Declares food VAT themselves. 
Kitchen Partner has NIP. Declares food VAT for all linked cooks. 
Payment flow 
DMB pays vendor net (food minus commission) 
DMB pays Kitchen Partner. KP pays cook 85% of net. 
EU food safety 
Restaurant has own Sanepid cert 
Kitchen Partner holds Sanepid for the certified kitchen space 
Customer sees 
Vendor name on listing. DMB on invoice. 
Home cook name on listing. DMB on customer invoice.
